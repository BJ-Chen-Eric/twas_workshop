# 額外資訊:GWAS Summary Statistics 檔案是怎麼來的?

這個 workshop 是從一份已經算好的 GWAS summary statistics 檔案開始的
(`gwas_ss/chr10_imputed_gwas.pheno.glm.logistic.hybrid`)——每一列
對應一個基因變異位點(SNP),附帶一個測試統計量,代表這個變異跟
性狀之間的關聯強度。你不需要重現這整個流程就能完成 workshop;這份
文件是給好奇「這個起始檔案到底是怎麼從原始的基因型樣本做出來的」的人
看的。

## 簡短版本

```
原始基因型樣本(依世代分)
        │  品質控管(QC)
        ▼
乾淨、合併後的世代
        │  族群結構與親緣關係校正
        ▼
QC 完成、可以做 GWAS 的資料集
        │  針對參考 panel 做 imputation(補值)
        ▼
補值後的基因型(變異數量比實際測量的多很多)
        │  關聯性檢定(例如逐一對每個 SNP 做邏輯迴歸)
        ▼
GWAS summary statistics ← 這個 workshop 從這裡開始
```

## 為什麼要先做 QC?

原始的基因分型資料會有一些很實際的問題:記錄的性別跟基因型不符、
某些變異位點分型失敗、資料集裡混進重複或意外有血緣關係的個體等等。
這些都要先檢查、過濾掉才能繼續——例如拿每個樣本記錄的性別跟基因型
暗示的性別做比對、丟掉缺失太多或違反 Hardy-Weinberg
平衡的變異位點、移除資料集裡偷偷重複或是跟別人有近親關係的樣本
(親緣關係如果沒處理掉,會讓假的關聯性被誇大)。

## 為什麼要校正族群結構?

如果某個祖源族群 A 的人剛好在你的樣本裡也比較常帶有這個性狀(跟任何
特定基因無關,純粹是族群歷史的緣故),那麼*任何*在不同祖源族群間
頻率不同的變異,看起來都會跟這個性狀假性相關。計算基因型的主成分
(PCA)、把它們當作關聯檢定的共變量放進去——再加上用親緣關係估計法
(例如 KING 方法)移除有血緣關係的個體——是處理這個問題的標準做法。

## 為什麼要做 imputation(補值)?

基因分型晶片或定序只會直接測量基因組裡的一部分變異。**Imputation**
會用統計方法把剩下的補起來:利用一個已經完整定序過的大型參考
panel(裡面鄰近變異之間的相關結構——linkage disequilibrium——已經
研究得很清楚),根據你的樣本直接測到的基因型跟參考 panel 裡哪些
haplotype 最像,去推測沒有直接測到的位置最可能的基因型。這也是為什麼
GWAS summary stats 檔案裡的列數(變異數)會比原本晶片直接測到的多
很多。

## 從補值後的基因型到 summary statistics 檔案

資料集做完 QC、校正過結構、也補值完成之後,實際的 GWAS 步驟會逐一
檢定每個變異:調整過上面那些共變量之後,這個變異的基因型(或補值出來
的 dosage)是不是跟性狀有關聯?結果就是每個變異一列——效應方向、
一個測試統計量(例如 Z-score 或勝算比)、還有 p 值。這張表*就是*
GWAS summary statistics 檔案——跟這個 workshop 裡
`run_native_tissue.py`/`run_native_tissue.sh` 讀進去的檔案是同一種東西,只是換成
真正的性狀、真正(QC 過、補值過)的世代,而不是這裡用的 toy 設定。

## 想看真正、詳細的版本嗎?

這份文件刻意只寫概念性的總覽,不是逐指令的操作手冊——完整的流程
(確切的 PLINK/bcftools/Beagle 指令、每一個 QC 門檻)放在專案內部的
開發文件裡,那份假設讀者有更多背景知識,也不在這個精簡過的 workshop
資料夾裡。如果想看,問問 workshop 的主辦人。
